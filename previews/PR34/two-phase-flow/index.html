Two-phase flow

Two-phase simulations use the same FlowSimulation entry point as single-phase flow. A TwoPhase object contains the interface and material properties; the velocity model independently selects one shared velocity or separate intrinsic liquid and gas velocities.

mesh = BlockTreeMesh(block_size=(16, 16), max_level=2)
interface = InterfaceField(
    mesh, (x, y) -> hypot(x - 0.5, y - 0.6) - 0.15;
    lipschitz=1,
)
physics = TwoPhase(
    interface;
    density=(1000.0, 1.0),
    dynamic_viscosity=(1.0e-3, 1.8e-5),
    surface_tension=0.072,
    gravity=(0.0, -9.81),
)
flow = FlowSimulation(
    mesh, physics;
    velocity_model=OneVelocityModel(),
    boundary=FreeSlip(),
)

A numeric surface_tension uses CGFM, the default conservative ghost-fluid formulation. Use a SurfaceTension object to select another method:

physics = TwoPhase(
    interface;
    density=(1000.0, 1.0),
    dynamic_viscosity=(1.0e-3, 1.8e-5),
    surface_tension=SurfaceTension(0.072; method=CSF()),
)

Choosing the velocity model

OneVelocityModel stores one face velocity and is the default. It is appropriate when a shared interfacial velocity is the intended closure.

TwoVelocityModel stores separate intrinsic phase velocities. Its two independent numerical choices are explicit:

velocity_model = TwoVelocityModel(
    interface_transport=FrozenInterfaceFluxes(),
    pressure_projection=CMDGFMProjection(),
)
flow = FlowSimulation(mesh, physics; velocity_model)

The alternative interface carrier is ProjectedLiquidVelocity, and the alternative pressure formulation is MimeticProjection. Its default uses jointly fitted smoothed-aperture rows; pass MimeticProjection(variant=:joint_face) for the CMDGFM-selected face-row layout. These are the two supported mimetic variants. See Two-velocity advection for their discrete definitions. A shared velocity initializer works with either model. To start the phases differently, pass a liquid/gas pair of fields or callables together with TwoVelocityModel().

Interface initialization and reconstruction

InterfaceField stores the physical liquid volume fraction. The level-set constructor treats phi(x,y) <= 0 as liquid and integrates it over each active cell. The function need not be a signed distance. When it is, pass lipschitz=1 to make pure-cell exclusion more reliable.

interface = InterfaceField(
    mesh, (x, y) -> ((x - 0.5) / 0.2)^2 +
        ((y - 0.5) / 0.1)^2 - 1;
    atol=1.0e-10,
)

For a piecewise-linear boundary, construct a PolygonIndicator instead of approximating the polygon by a nonsmooth level-set function. Cell fractions then come from exact polygon clipping and do not depend on a quadrature tolerance:

polygon = PolygonIndicator([
    (0.2, 0.1), (0.8, 0.1), (0.7, 0.6), (0.3, 0.7),
])
interface = InterfaceField(mesh, polygon)

reconstruct! builds local PLIC geometry and curvature. Height functions are preferred where a suitable column exists, with geometric and Weymouth–Yue fallbacks near complex topology. Unavailable curvature is kept as NaN; it is not silently replaced by zero. The reconstruction, force, contact-angle, and refinement choices are documented together in Remmerswaal (2023).

For a single-valued interface, interface_height returns its physical coordinate along an adaptive-mesh column. This is useful for wave diagnostics:

amplitude = Diagnostic(
    :amplitude,
    state -> interface_height(state.interface; direction=:y, position=0) -
        mean_height,
)

Transport and material properties

The interface uses conservative directional Weymouth–Yue transport. Liquid and gas face volumes add to the total open-face volume, and stable_timestep includes the interface-volume CFL restriction. PhaseScalar and phase momentum reuse the same phase fluxes rather than reconstructing a separate carrier.

Density is linearly volume averaged at the locations needed by projection. Dynamic viscosity is geometrically averaged at normal- and shear-stress locations. Set both phase viscosities to zero for inviscid flow; otherwise both must be positive.

Surface tension choices are:

MethodUse
CGFMdefault conservative ghost-fluid force
CSFcontinuous-surface-force formulation

Gravity and surface tension use the same compatible pressure-gradient locations as the projection. Nonzero gravity is not supported along a periodic direction.

Embedded solids and contact angles

GeometryField represents a fixed solid with phi(x,y) <= 0. Pass it to both the interface (when the phases touch the solid) and the simulation:

geometry = GeometryField(mesh, wall_levelset)
interface = InterfaceField(
    mesh, phase_levelset;
    geometry,
    contact_angle=(nothing, nothing, pi / 2, nothing),
)
physics = TwoPhase(
    interface;
    density=(1000.0, 1.0),
    dynamic_viscosity=(1.0e-3, 1.8e-5),
    surface_tension=0.072,
)
flow = FlowSimulation(
    mesh, physics;
    geometry,
    boundary=FreeSlip(),
)

The four contact-angle entries correspond to left, right, bottom, and top domain walls. Embedded-wall examples can pass one angle. Closed solid faces carry no phase, surface-tension, or gravity flux.

Adaptive refinement

Use InterfaceRefinementIndicator for a fixed band around the phase interface and CurvatureRefinementIndicator where the local curvature needs more resolution. Add them through Adaptivity:

criteria = (
    InterfaceRefinementIndicator(interface; level=2),
    CurvatureRefinementIndicator(interface; cells_per_radius=8),
)
flow = FlowSimulation(
    mesh, physics;
    adaptivity=Adaptivity(criteria=criteria),
)

Regridding conserves phase volume and rebuilds interface, transport, pressure, and diffusion workspaces after a real topology change. The original level-set function is used only for initialization; later refinement transfers the reconstructed physical interface.

Practical limits

  • Interface transport currently supports impermeable or periodic boundaries.
  • The solver uses one global time step; there is no level subcycling.
  • Curvature and contact-angle accuracy should be checked by mesh refinement.
  • Tiny phase fractions below fraction_floor are removed to keep intrinsic scalar and velocity recovery well-defined.
  • The package is two-dimensional and uses shared-memory execution.

The runnable examples include capillary waves, interfacial instability, sessile droplets, and embedded-wall cases. Every Navier–Stokes two-phase example accepts either velocity model; the instability example defaults to two velocity.
