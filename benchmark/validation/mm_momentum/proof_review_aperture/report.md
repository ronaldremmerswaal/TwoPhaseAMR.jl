## Details

### (a) Gram block rows (`scripts/step03_block_rows.py`)
Port formula `B = R G^+ R^T + S`, `S = 1/2 D Q D` plus the slaved closing edge (`v_G = -sum L_q v_q/|eta|`).
1. Single partial side `(b,0,0,0)`: `G = b (y* + 1/2) e_y e_y^T`, clamp puts `y*` at `-1/2 + 0.01`, `R = (0, -0.01 b)`, `B = 0.01 b` (checked for `b = 1 ... 1e-9`); `S = 0` (the closing edge cancels it).
2. Tiny liquid corner `(b,0,0,b)`: `G = b [[p, p-b/2],[p-b/2, p]]`, eigenvalues `b(2p - b/2)`, `b^2/2`, `p ~ 0.005`; `R` is the swapped `-G`, so `B = Pi G Pi` and `S = 0` identically (for <= 3 edges `Q` has rank 1 and the closing correction cancels it). Row/b = 0.0141. For `b <= 1.4e-5` the eigenvalue `b^2/2` falls below the pseudo-inverse cut `1e-10` and the block is rank one (`lambda_min/lambda_max < 1e-8`); for `b <= 7e-9` both eigenvalues are cut, block 0, diagonal 0, the value is lumped.
3. Straight PLIC line within `delta` of a corner (closed polygon data): `sup row/b = 0.9998, 0.99996, 1.0000, 1.0000` for `delta = 1e-2, 1e-4, 1e-6, 1e-8` (about 6000 lines each, all values with wetted length <= 0.05); `M_ff/b^2 in [1.0, ...]`, `M_ff/b <= 0.5`. So for closed data the claim holds with constant 1; the diagonal is **between `b^2` and `b/2`**, i.e. `O(b)` is an upper bound only (this matters for (a4)).
4. Not closed data (apertures averaged from two traces, 0.3 rad / 0.1 h perturbation, 8000 draws): `sup row/b = 11.5` at `delta = 1e-3`, **4147** at `1e-6`. Explicit counterexample: apertures `(0.2825, 0, 0.3125, 1e-8)`, starts `(T,T,T,F)`, liquid block: pressure point `x* = (6.95, -0.167)`, `G` eigenvalues `7.5e-8`, `0.30`; the block is flagged consistent; the row of the value with `b = 1e-8` is `(2.07, 2.07, 7e-8)`. Mechanism: `R_q G^+ R_r` with `G^+ ~ 1/(7.5e-8)` and `R_r = O(1)`. Whether such data occur in the PLIC data path of the package is not decided here (averaged traces do give 3-4 crossed sides). Corrected statement: rows are `O(b)` for data that close up to a straight line (and observed `<= b`), not for arbitrary shared apertures.

### (a) Continuity and the size of the event (`scripts/step04_continuity.py`)
* Line through a corner, cell stays cut: `|dB|/eps <= 75`, `|dx*|/eps <= 50` (eps = 1e-6, 1e-9, lines with `min(|n_x|,|n_y|) > 0.01`): continuous. The reason: for straight-line data the crossed points lie on the chord and the projection onto the symmetry line (perpendicular to the chord) removes the dependence on which crossings are included.
* `cut -> uncut` (tiny wedge of length 1e-9 dies): the block of the **other** phase is `R R^T + S` with `x*` at the corner, while the uncut cell gives `1/2 I`: jump median 1.483 (min 1.479, max 1.490). In the lattice (`step05`, last block) the liquid `M` on the common dofs jumps by 1.48 (diagonal 1.0 -> 2.48) when two values of length 1e-9 are born. Momentum and energy of the cell depend on `x*` only through the net wetted flux `b^T u` (`N^T B u = R^T u = R_0^T u - x* (b^T u)`; the quadratic form likewise): zero jump for `b^T u = 0` (2e-9), O(1) otherwise (2.7 / 19).
* Generic data, `a_q = 0` vs `1e-9`: median `|dx*| = 0.16`, 78% above 0.05, median `max|dB| = 0.19`.
* Dying value in cells with >= 3 wetted sides: median off-diagonal/`M_ff` = 271, 2.8e4, 2.9e6 for `eps = 1e-3, 1e-5, 1e-7`, median `M_ff/b^2 = 1.67`, median off-diagonal/`b = 0.7`.

### Identities needed for (c) (`scripts/step06_identities_merge.py`)
Setting: face-level transport `m+ u_W = m u_F - dt C u_F` with `Z_F^T C = 0`, `dt C Z_F = -(m+ - m) Z_F`; merge fractions `S` (class-preserving, column sums 1; `W~ = S m`, level-wise: `S` at the old level with `M`, `S+` at the new level with `M+`); the code's update `M+ u+ = M+ u + S+ m+ (u_W - u_F) + (1-theta)(E~ u - E~+ u)`, `E~ = M - W~`.

* Needed by `prop:obstruction`: nothing (linear algebra) plus `Z^T dW~ Z = 0`. Needed by `prop:theta` (a): only `u_W = u_F` for constants (vanishing increments). Needed by `prop:flux`, `prop:theta` (b), (c), `prop:redistribution` (b), (c): `Z^T C~ = 0` and `dt C~(Z) = -(W~+ - W~) Z` with `C~` the **flux of the update actually coded**, and, for (c), `C~ + C~^T = -W~dot`.
* **The merge does not keep both identities for any locally merged covector.**
  - Merged covector `C~ = S+ C` (fractions of the new level): `Z^T C~ = 0` holds (err 6e-16); `dt C~(Z) = -(S+ m+ - S+ m) Z`, which differs from `-(W~+ - W~) Z` by the reassignment `(S+ - S) m Z` (0.094 in the test, formula verified to 8e-16). It vanishes only for frozen fractions (`S+ = S`).
  - Flux implied by the update (theta = 0): `L(u) = -[(W~+ - W~) u + S+ m+ (u_W - u_F)]`: `dt L(Z) = -(W~+ - W~) Z` holds (4.6e-16, constants preserved iff `E~ Z` invariant: the iff of `prop:flux` carries over), but `Z^T L != 0` (0.106): `Z^T L u = -(mu+(u) - mu(u))`.
  - Because `W~` depends on `M_ff` through kappa (and on the lump), `S+ != S` whenever `kappa M_ff` crosses `m_f` (`k_f/m_f` changes by O(1) while `m_f` does not): the second identity needs a flux that reassigns parcel momentum `(S+ - S) m u_F` between donors. With that term `C~2 = S+ C - (S+ - S) m(.)/dt` **both identities hold** (2.8e-15) for the transport of the merged parcel momentum `q = S m u_F`; but the update uses `W~ u` (dof velocities), and `W~ u != q` unless every merged face carries its donor's velocity: the defect is exactly `mu`.
* Hence: (a) of `prop:theta` carries over; (b) and (c) of `prop:theta` and the momentum/energy part of `prop:redistribution` carry over **up to the merge defect** `mu+(u) - mu(u)` (momentum) and `1/2 u^T W~dot u - u^T S C u_F - u^T S mdot u_F` (energy); `prop:flux` carries over with `C~ :=` the flux implied by the update; `prop:obstruction` carries over verbatim. In particular the DP momentum restoration (`defect = Z^T E~+ u - Z^T E~ u - ...` in `:increment_conservative`) does not contain `mu`, so its "exact momentum" claim is not recovered with the merge unless `mu+ - mu` is added to `d_k` [code reading, not run].
