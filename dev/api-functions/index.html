TwoPhaseAMR.advect! — Method
advect!(field, advecting, dt, workspace;
        scheme=LaxWendroff(),
        amr_interface_scheme=default_amr_interface_scheme(scheme))
advect!(velocity, dt, workspace;
        scheme=LaxWendroff(),
        amr_interface_scheme=default_amr_interface_scheme(scheme))

Advance both components of a staggered vector field. Within one coordinate sweep, both component tendencies are evaluated from the same input and then both components are published. The next coordinate sweep therefore consumes one consistent intermediate vector rather than updating x and y velocity components separately. The one-velocity shorthand also uses each published intermediate as its advecting field. By default LW and centred transport use MC on non-regular AMR connections, upwind remains globally upwind, and a selected three-point scheme is retained.

TwoPhaseAMR.advect! — Method
advect!(field, velocity, dt, workspace;
        scheme=LaxWendroff(),
        amr_interface_scheme=default_amr_interface_scheme(scheme))

Advance a directional face field using conservative fluxes through its staggered control volumes. Lax–Wendroff uses two full directional sweeps, publishing the first intermediate before evaluating the second and alternating x/y with y/x order on successive calls. The variable-coefficient LW predictor includes the directional dual divergence of the transporting velocity; the two directional divergence terms cancel for a divergence-free velocity only after both sweeps. On a uniform constant-velocity line it reduces to classical one-dimensional LW. By default LW and centred transport use MC on non-regular AMR connections, upwind remains globally upwind, and a selected three-point scheme is used at the interface as well.

TwoPhaseAMR.amrfield! — Function
amrfield!(axis, source, field; phase_rendering=:cell, colormap=automatic,

          blocks=false, oversample=2, kwargs...)

Makie recipe that draws field field of an AMR frame. source is a stored Frame, an Observable of frames (animations swap frames without rebuilding the figure), or a VisualizationFieldRegistry, whose current state is captured once.

The field is an image of rasterize over the visible part of the domain, with oversample samples per screen pixel along each axis. The plot's data limits are the domain, so fieldaxis(...; camera=:fit) fits the domain, and Colorbar(gridposition, plot) draws the colour bar. amrfield creates its own figure and isotropic axis. Load a Makie backend first.

TwoPhaseAMR.convection! — Method
convection!(destination, advected, velocity, dt, workspace;
            scheme=LaxWendroff(),
            amr_interface_scheme=default_amr_interface_scheme(scheme))

Evaluate the conservative staggered convection operator div(I(velocity) q) on owned dual control volumes. scheme may be Upwind(), Centred(), LaxWendroff(), Fromm(), Minmod(), MonotonizedCentral(), VanLeer(), or Superbee() (the corresponding symbols are also accepted); the default is LaxWendroff().

For LW and positive dt, the returned rate is the effective rate of the next directionally split step. Each step has two full sweeps; their order alternates between x/y and y/x on successive advect! calls. Every sweep consumes the preceding intermediate field. Thus destination == (advected - advect(advected, dt)) / dt without advancing the workspace's order flag; x and y fluxes are not accumulated from one old state. At dt == 0, the limiting spatial operator is evaluated directly.

For an all-centred operator (scheme=Centred() and amr_interface_scheme=Centred()), the face value is the equal-weight average. On every supported periodic mesh this makes twice the convection-matrix diagonal equal the volume-weighted interpolation of the primary cell divergence. The operator is therefore volume-weighted skew-symmetric for a discretely divergence-free velocity, including across refinement interfaces.

On a mixed-level or bounded mesh, amr_interface_scheme selects the state used on non-regular factored and wall-adjacent connections. Its default follows scheme: upwind remains upwind, centred and LW use MC, and a three-point scheme uses itself. Upwind at an AMR interface is rejected unless the bulk scheme is also upwind; an interface-only first-order closure has poor accuracy. The four limited variants revert to upwind at a local extremum. A hanging connection without an unambiguous upstream direction also falls back to upwind. Explicit Centred() retains the diagonal and skew identities throughout the mesh. The keyword is accepted but has no effect on a uniform fully periodic mesh.

source

TwoPhaseAMR.diagnosticsgrid! — Method
diagnosticsgrid!(gridposition, source; names=:all, group=:dimension,
                 transform=:raw, cursor=nothing, until=nothing,
                 references=Dict(), diagnostic_options=nothing,
                 direction=:column, legend=:rt, xlabel="t")

Plot simulation diagnostics in a figure grid position, one axis per group, and return the axes. source is a SnapshotStore or Recorder (its mirrored diagnostics), a FlowSimulation, or a DiagnosticCollection; names selects diagnostics (default: all).

  • group=:dimension plots diagnostics with the same kind, physical dimension, and scale on one axis (see diagnostic_groups); group=:name gives every diagnostic its own axis. An axis with one diagnostic is titled by its label and dimension, a shared axis by the quantity, with a legend. Vector diagnostics are split into labelled components, and :log groups use a logarithmic axis.
  • diagnostic_options optionally overrides individual groups. It is a vector of named tuples (; names, scale, hidden), for example [(; names=[:linear_momentum], scale=:log, hidden=[(; name=:linear_momentum, component=2)])]. names must be exactly the symbols in one selected group, in any order; scale is :linear or :log, and hidden lists one-based (name, component) keys. Groups not listed retain their metadata scale. Duplicate groups or components, unknown names, and out-of-range components are errors. Hidden components and their corresponding reference lines are omitted from the plot, legend, and automatic limits. With nonempty overrides, unsampled groups and wholly hidden groups remain as empty axes. Logarithmic plots omit nonpositive values, not their absolute values.
  • transform=:relative plots the change relative to the first sample, (v - v₀)/|v₀|.
  • cursor is a time or an Observable of times, drawn as a vertical line on every axis; animations use it to show the current frame.
  • until (a time or an Observable of times) shows only the samples up to that time. With an Observable, the source is read again whenever it changes and the axes follow the data, so the diagnostics of a running simulation grow.
  • references maps a diagnostic name to a function of time or to the name of another diagnostic. The reference is drawn dashed on the same axis, and a referenced diagnostic gets no axis of its own.
  • direction=:column stacks the axes and links their time axes; :row places them side by side. legend is an axislegend position or nothing.

Load a Makie backend first.

TwoPhaseAMR.dynamic_viscosity — Method
dynamic_viscosity(interface; viscosity, averaging=HarmonicViscosityAveraging())

Return the cell-centred dynamic viscosity used by the one-velocity diffusion operator, mixed from the phase viscosities with the conditional liquid fraction c of the open fluid part of the cell and the phase-viscosity averaging rule averaging.

HarmonicViscosityAveraging (the default) gives 1 / (c / mu_liquid + (1 - c) / mu_gas), the series conductance across the interface in a cell; GeometricViscosityAveraging gives the thesis' diffuse mixture mu_liquid^c * mu_gas^(1-c). The same rule averages the viscosity of a stress row from the cell quarters it spans, see _fill_stress_weights!.

TwoPhaseAMR.export_animation — Method
export_animation(path, recording; field, source=:stored, window=nothing,
                 frames=:keyframes, fps=20, duration=nothing, nframes=nothing,
                 sim_per_second=nothing,
                 diagnostics=nothing, diagnostic_options=nothing, size=automatic,
                 px_per_unit=1, camera=:fit, colorrange=nothing,
                 colormap=nothing, phase_rendering=:cell, interface=true,
                 geometry=true, blocks=false, interfacecolor=:black,
                 blockcolor=(:gray40, 0.8), decorations=:minimal,
                 title=automatic, group=:dimension, references=Dict(),
                 transform=:raw, arrangement=:auto, capacity=32,
                 progress=nothing, cancel=nothing)

Animate field field of a recording as a GIF or video (.gif, .mp4, .mkv, or .webm). An animation shows either stored or live frames, never a mix:

  • source=:stored (default) samples the stored frames of a SnapshotStore or Recorder after (or during) the run. frames=:keyframes (default) or :all chooses the candidates. Only frames with times in window = (t0, t1) are candidates; without a window the whole recording, from its first to its last candidate frame time, is used. Video time advances linearly in simulation time: output frames are uniformly spaced over the window and each shows the candidate frame nearest to its target time, with ties going to the earlier frame. Stored frames are therefore repeated when the recording is sparse and skipped when it is dense; an animation never maps output frames to stored frames one-to-one. fps (default 20) sets the frame rate. duration in seconds sets the number of output frames to round(fps * duration) + 1, including the first and last frame, so the play time between them is duration; without it the duration scales with the number of candidate frames, clamp(count / fps, 2, 20) seconds. Give nframes instead to set the count directly. The automatic title is the simulation time of the displayed frame. The colour range is colorrange if given, else the registered range, else the range of the field over the candidate frames, symmetric about zero for vorticity and diverging colormaps. Optional progress(i, n) runs after each output frame is submitted to the encoder; cancel() is a zero-argument predicate checked between frames and around finalization. On cancellation the function returns nothing, removes its partial output, and leaves any pre-existing destination intact. Otherwise it returns path. Callback failures are propagated.
  • source=:live records the frames of a Recorder as the run produces them (previews and keyframes, including previews that retention later thins) and returns a handle at once; start it before simulate! and close it afterwards to write path. Video time also advances linearly in simulation time here: output frame k shows the arrived frame nearest to t_start + (k - 1) * step, where t_start is the simulation time of the newest stored frame when the recording starts and step = sim_per_second / fps. Without sim_per_second, it targets ten seconds of video for the run's remaining simulation time (when a Studio driver knows its final time), else for the stored frames' span, and falls back to 1. A frame that arrives decides every output time up to its own time, using one frame of look-ahead; a sparse stream repeats frames, a dense stream skips them, and the final frame is held for the remaining output times. fps (default 20) sets the encoding frame rate. Frames are encoded on a thread other than the solver's, through a queue of capacity frames: the solver never waits, and frames that arrive while the queue is full are dropped and counted. The handle reports encoded, dropped, and the ids of the frames written. window, frames, duration, nframes, progress, and cancel apply only to source=:stored. Without a registered or given range, the colour range is that of the frames recorded so far. Viewing or reading the store from other tasks does not affect the recording.

The figure is built once and the frames are swapped through an Observable. Makie's video stream pads odd resulting pixel widths and heights by one and rounds noninteger frame rates to the nearest integer. The axis limits follow camera (see fieldaxis; :fit is the domain) and are the same on every frame. title is automatic (t = …), nothing, a string, or a function of the frame. interface, geometry, and blocks select the overlays of amrfield!; interfacecolor and blockcolor colour the interface and block-outline lines. The figure follows the active Makie theme (with_theme): a dark theme with light text, light line colours, and a colormap whose neutral is dark (such as :berlin) give a dark variant. diagnostics (names, or :all) adds diagnosticsgrid! panels, grouped by group, with a time cursor synced to the frame; live diagnostics grow with the run. diagnostic_options applies the per-group scale and component visibility described by diagnosticsgrid! to both stored and live exports. arrangement=:right stacks diagnostics to the right, :below places them beneath the field, and :auto chooses the right for one field or below for multiple fields. Load a Makie backend first.

implicit_midpoint_diffusion!(destination, convected, old_velocity,

                             max_cycles=100)

Apply the Crank–Nicolson/implicit-midpoint viscous substep

source
TwoPhaseAMR.project! — Method
project!(velocity, pressure, solver, dt, workspace;
         velocity_boundary=nothing, boundary_time=0, compatibility=:project,
         tolerance=sqrt(eps(T)), max_cycles=100)

Project a pressure-predicted velocity using the weighted gradient in the solver's Poisson operator. The input pressure is the old physical pressure and the velocity predictor must already include its pressure acceleration. The increment φ solves the compatible projection of -diffusion*D*G_kappa*φ = -D*u*/dt; the update is u <- u* - dt*diffusion*G_kappa*φ, p <- p + φ. Open normal faces use homogeneous Dirichlet increments and participate in this correction; fixed normal faces use homogeneous Neumann increments. Each unanchored component has a volume-mean-zero increment. A single connected component retains the incoming physical pressure mean; on disconnected domains the accumulated pressure is gauged independently on each unanchored component. velocity_boundary must have the same open sides as the Poisson operator's velocity_boundary; a mismatch in either direction raises ArgumentError. The supplied open-face velocities are retained as predictor data. The returned LinearSolverStats.compatible compares the largest removed strong componentwise RHS mean multiplied by dt^2 with the requested tolerance, independently of converged. The component means represent a part of the projection RHS that a pressure correction cannot remove. An incompatible projection warns once per workspace. Reusing a nonzero pressure field with an unpredicted velocity accumulates projection impulses; use zero scratch pressure for an absolute projection. Following Basilisk, tolerance bounds the fractional volume defect associated with the linear-solve residual: dt^2 * norm(residual, Inf) <= tolerance (up to the roundoff floor). A shortened simulation step can additionally retain part of its inherited divergence.

TwoPhaseAMR.project! — Method
project!(velocity, pressure, solver::CMDGFMProjectionSolver, dt, workspace;
         tolerance, max_iterations, warm_start=true)

Apply the conservative multidimensional ghost-fluid projection. The predictor must already contain -dt times the current projection's weighted gradient of the input physical pressure. The nonsymmetric two-block system solves for a pressure increment and mixed-face gradient jump; velocities are corrected by that increment before it is added to pressure. Pass a zero pressure field for an absolute velocity projection.

_reference_dt must be finite and at least dt. When _inherited_cell_flux supplies the pre-transport negative integrated mixture divergence, the projected cell flux targets (1 - dt / _reference_dt) times that saved flux, while every resolved current-interface normal-velocity jump targets zero. Convergence measures the mixture defect relative to its target and the actual normal-velocity defect; the reported mixture and normal defects always describe the actual projected state. Without an inherited flux, the mixture flux also targets zero.

BiCGSTAB uses a tree-GMG pressure/active-jump-ILU block preconditioner by default. A whole-system ILU remains available for comparison. Residual replacement checks the omitted gauge rows as well as the retained system and counts all attempts against max_iterations. warm_start tries residual-checked previous-increment/current-jump guesses; false retains the zero-start reference solve with the same convergence criteria.

TwoPhaseAMR.simulate! — Method
simulate!(flow::FlowSimulation, final_time; dt=flow.default_dt, options...)

Advance flow from its stored time to the absolute final_time, reusing its workspace. The low-level simulation result is returned with total_steps, total_mesh_updates, and total_unresolved_curvature_faces added; the last is the cumulative number of unresolved surface-tension faces over all calls. Calling this method again continues the same run. For automatic stepping, the unmodified step proposal is retained across consecutive calls. To avoid a tiny final step, a proposal leaving less than 1e-6 of itself is stretched to the target. A target between physical steps can change the trajectory. If automatic step selection initially has an infinite stability bound, the step is capped at one 128th of the requested interval. The initial time is owned by flow and therefore cannot be passed as a keyword.

source
TwoPhaseAMR.simulate! — Method
simulate!(velocity, pressure, solver, final_time, workspace;
          time=0, dt=nothing, cfl=0.45, force=nothing,
          diagnostics=NoDiagnostics(), step_offset=0,
          observer=NoObserver(),
          tolerance=sqrt(eps(T)), max_cycles=nothing)

Advance to final_time. If dt is omitted, a stable step is chosen initially and retained while it remains below the current bound, which also reuses the shifted viscous hierarchy and bottom factorization. The cfl keyword must lie in (0, 1] for one phase and (0, 1/2] for two phases; each step is checked against the same bound at the top of that range, so every step the bound returns is accepted. Consecutive automatic calls using the same fields, solver, workspace and topology retain the unmodified proposal, not the last step adjusted to final_time. If the next step would leave less than 1e-6 of the proposal, it is stretched to reach the target instead of leaving a tiny final step. Formulations that retain inherited divergence use the largest of the proposal, the previous actual step, and the current step as the reference; the first step uses its proposal. The previous step is retained across fixed and automatic calls when the field and solver identities, time and mesh topology still match. A field-level step! or project!(flow) invalidates that history and the automatic proposal. A full step!(flow, dt) retains the defect reference but resets the automatic proposal. After a regrid, the transfer may create a new defect. Its reference is the current unshortened proposal, also used for the two-velocity regrid projection, until the next physical step establishes a new actual step. A chunk boundary between physical steps nevertheless introduces a shortened step and can change the trajectory. If the initial bound is infinite, the step is capped at one 128th of the requested simulation interval, ensuring at least 128 steps before the target time. Returns the final time, number of steps, latest physical-step projection statistics, the accumulated projection statistics of this call (projection; see ProjectionRunStats), the number of topology changes, unresolved_curvature_faces, the sum of unresolved surface-tension faces across completed steps in this call, and stopped, which is true when the observer ended the run early. The latest step's unresolved-curvature count is available as workspace.unresolved_curvature_faces[]. When the solver has refinement indicators, they are evaluated after a successful physical step. After a topology change, two-velocity flows project the transferred velocities onto the new mixture incompressibility constraint before the next step; the transferred physical pressure is retained. For one-velocity flows, the returned pressure statistics include compatible, which is independent of linear-solve convergence. An incompatible pressure projection warns once per workspace, including across topology rebuilds and successive calls using that workspace.

The observer (an AbstractObserver, such as a Recorder) receives the initial state, every completed step, and the final state through observe!; diagnostics are recorded before each event. At :initial the StepInfo carries an independent-step procedure that advances copied state without replacing or subdividing a step on the actual simulation path. Where applicable, the independent step uses that physical step's reference for the inherited defect. After every step simulate! polls stop_requested; when it returns true, the run ends at that step boundary.

      max_cycles=nothing)

Advance one split momentum step followed by one incremental pressure projection. Both single- and two-phase configurations execute the same staged procedure. force, when present, is sampled as force(x, y, time, axis) at the time midpoint and added to the transported state before diffusion, preserving the single-phase solver's established splitting. TwoPhaseAMR.step! — Method

Advance one two-velocity Navier–Stokes step.

The geometric interface and both intrinsic phase velocities use the same transport stage as the passive two-velocity API. Body force, surface tension, and gravity modify the momentum predictor. CMDGFM subtracts the old physical pressure gradient from the predictor, then corrects velocity with a pressure increment that is added to the physical pressure.

For a shortened CMDGFM step, the old-aperture mixture flux is scaled by the reference step, which must be at least dt. Viscosity acts implicitly on the phase-mass weighted one-velocity state; its common increment is applied to both phases.

The two-velocity projection keeps a Neumann pressure boundary and cannot correct open normal velocities. Boundary preparation extrapolates each phase; Outflow() balances its net flux, while an absolute phase flux exceeding 256eps(T) with only ZeroGradientVelocity() open sides throws ArgumentError. This per-phase check sums outward intrinsic velocity times face area and geometry aperture, omitting faces whose phase velocity is absent.
